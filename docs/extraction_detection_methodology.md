# Extraction and detection methodology

PDF page text is extracted with PyMuPDF. Pages below 30 characters with embedded images are OCR candidates; missing Tesseract or OCR exceptions create extraction failures and block release. Sparse pages without images are explicitly uncertain. DOCX paragraphs and rows are kept separately in order; PPTX text and table rows retain slide and shape/table references. Embedded images in Office files are flagged because image OCR is not implemented in this version.

Detection combines case-insensitive structured patterns for emails, North American phone numbers, and explicitly labeled employee/account/government identifiers with a deterministic lexical context detector for two-part names following `Name` or `Contact` labels. Address detection also requires an explicit address label. The context detector uses token boundaries and capitalization rather than a statistical NER model; this keeps the demo local and avoids downloading an opaque model, at the cost of missing unlabeled or atypical names. This deliberately avoids classifying arbitrary dates, amounts or organization names as personal information. Structured patterns are configurable in `pii_guard/detection/patterns.py`. Findings include span offsets and provenance. A labeled name/address is medium confidence and is flagged for review when confidence is below 0.85.

This is a demonstrator, not a comprehensive DLP engine: contextual NER, international identifiers, multilingual content, handwriting OCR and format-preserving PDF/DOCX/PPTX redaction are out of scope. No-findings does not prove no PII exists.
